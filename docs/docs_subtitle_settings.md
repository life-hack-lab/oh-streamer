# 字幕設定與模型管理

最後核對：2026-10-18（對照實際程式與官方文件）。模型名稱、免費額度、價格會變動，
本文只做定性說明，並以各服務官方頁面為準，查詢日期 2026-10-18。介面不承諾固定秒數、
永久免費或剩餘額度。

## 1. 字幕方案：雲端（推薦）／本機／自訂

佇列設定的「字幕方案」有三種，各方案的設定與憑證分開保存，來回切換不會遺失：

| 方案 | 用途 |
| --- | --- |
| 雲端（推薦） | 以 Groq 辨識並翻譯；可選配 Azure Translator 快速初稿 |
| 本機 | 本機 Whisper 辨識＋Sakura 翻譯，不使用任何雲端服務 |
| 自訂 | 辨識、翻譯、選填初稿各自選本機或雲端模型，可混搭 |

方案變更只影響之後新排程的工作；已排程工作保留當時的設定快照。新安裝預選雲端，
但未填金鑰時顯示「待設定」，不會自動啟動字幕。

## 2. 首次雲端設定

### 會傳出什麼

- 語音辨識：影片的音訊片段會上傳到辨識服務。
- 翻譯：辨識出的對白文字會送到翻譯服務。
- 影片畫面不會上傳。費用與用量依服務商規定，可能計費；請自行確認所處理的內容符合服務商的使用條款與所在地法規。

### 雲端外連設定

介面不再提供獨立的「允許使用雲端字幕服務」開關。使用雲端方案、驗證雲端連線，
或自訂方案選用雲端模型時，會自動啟用設定鍵 `subtitle_cloud_enabled`。
雲端頁保留音訊與字幕文字會透過 HTTPS 傳送至服務商的說明。

未設定金鑰與模型時仍不會自動產生字幕。本機方案不使用雲端候選；切回本機不清除
已保存的雲端連線與允許狀態。底層外連檢查仍保留，供執行時與命令列使用。

### 只用 Groq（最簡流程）

1. 在雲端頁「Groq 連線」按「＋ 新增」，填寫名稱與 API 金鑰，按「驗證並儲存」。不需要輸入模型名稱。
2. 一次設定會同時配置辨識與翻譯兩項能力，驗證結果分開顯示。其中一項失敗時，成功的那項
   會保留，修好後重新驗證即可。
3. 實際流程：辨識 → 翻譯一次 → 發布。不會把同一模型拆成「初稿＋精修」兩次呼叫。
4. 辨識驗證預設使用內建的短語音樣本，會實際呼叫服務，可能消耗少量用量。

### 多組 Groq 金鑰（連線池）

- 主列表只顯示啟用狀態、名稱、能力驗證結果與「編輯」。不要求填寫組織。
- 最多保存 10 組連線，避免一次切換耗盡既有排程的嘗試預算。
- 「編輯」原地展開，可改名稱、使用順序、替換金鑰或刪除；金鑰留空保留原值，儲存後不回顯。
- 勾選「限額時自動切換」後，辨識與翻譯各自依順序使用已啟用且能力驗證成功的連線。
  短期限流遵守服務等待時間，長期限額切換備援；全部冷卻時等待恢復。
  關閉自動切換時，只使用第一個啟用的連線，不切換其他金鑰。
- 既有連線不重建；首次調整連線池時，沿用原本主模型與備援所用的連線，其他連線預設停用。
- 被佇列工作或其他字幕設定引用的連線不可刪除；其他連線可一併移除所屬模型。
- Groq 同組織金鑰仍可能共用額度，換 key 不增加額度。介面不推測剩餘額度或假設不同 key 的額度獨立。

### Groq＋Azure（選填快速初稿）

展開「選填：Azure Translator 快速初稿」，填入 Azure 金鑰；資源若為區域型，須填 Region
（例如 `eastasia`）。全球（global）資源可留空。勾選「使用 Azure 初稿」後：

辨識 → Azure 初稿（先發布，讓字幕盡早出現）→ Groq 精修（覆蓋初稿）。

Azure 初稿失敗時自動降級為「Groq 直接翻譯」，不會讓整套字幕失敗；這與主要翻譯失敗是
兩件事，介面分別標示（見第 6 節）。

### 本機

本機頁顯示推薦組合（Whisper＋Sakura）的就緒狀態，按「使用推薦配置」套用。模型下載與路徑
沿用「管理模型與連線」。進階才有融合雙模型、精確模型、裝置與實驗性核顯選項。純本機不會使用任何雲端服務。

### 自訂

分別選擇辨識、翻譯、選填初稿；各選單只列出能力相符的模型。頁面顯示資料流摘要
（辨識 → 初稿 → 精修）。選用雲端模型時會自動啟用 `subtitle_cloud_enabled`（見第 2 節）；若該設定鍵被關閉，頁面會出現警告，雲端模型仍不會被呼叫。

## 3. 進階設定

- **Groq Whisper 策略**：「自動」允許同服務的 `whisper-large-v3-turbo`／`whisper-large-v3`
  在限流或故障時互相備援；「固定」鎖定單一模型，不會自動切換。
- **處理策略**：隨播放與修復進度處理（跳轉到未處理段落時優先）或整部預先處理。整部預先處理會用完整影片的用量。
- **前段字幕長度**、日文辨識字幕軌、多字幕比較、實驗性核顯翻譯，見第 8 節與原有設定。

## 4. 服務連線管理

「管理模型與連線」的「服務連線」分頁以連線為單位顯示：憑證保護方式、端點、Region，
以及辨識／翻譯兩項能力各自的驗證狀態。

- **金鑰輪替**：在該連線卡片原地輸入新金鑰並驗證，既有模型引用不變，不會重複新增模型。
- **刪除**：連線若仍被任何字幕設定（含備援清單）或佇列工作引用，會被拒絕並在卡片內顯示原因。
  先移除引用再刪除。
- 連線驗證成功不等於模型可用：辨識需實際語音與時間碼，翻譯需逐行對應正確。

## 5. 備援與重試

進階設定的「模型備援設定」提供兩份獨立的有序清單：辨識備援、主要翻譯備援。預設為空；
可加入本機模型、同服務其他模型或其他雲端服務的模型，可上移、下移、移除，只列出已設定且
能力相符的候選。純本機方案加入雲端候選時，會自動轉為自訂方案，不會暗中外連。

語意：

- **重試**：暫時性錯誤（限流、網路、逾時、服務端錯誤）先對同一候選有限次重試（預設 1 次，0～3），
  再換下一個候選。總嘗試次數有上限（預設 4，1～12），候選去重且不循環。
- **Retry-After**：服務回報的等待時間會被遵守；短等待可被取消，不佔住 GPU。等待過久
  則直接視為該候選失敗。
- **冷卻**：候選失敗後進入冷卻（預設 60 秒，1～3600），期間其他區塊不再撞同一服務。
- **主服務恢復**：冷卻結束後，下一個區塊只試探一次主服務；成功才恢復使用。
- **認證錯誤／模型不存在**：不反覆重試同一候選，改試已設定的備援。取消與無語音不觸發備援；
  內容被拒絕不會自動轉送其他服務。
- **粒度**：以失敗的辨識片段或翻譯批次為單位，不重做整部影片。
- **純本機不使用雲端**：本機方案，或 `subtitle_cloud_enabled` 關閉時，雲端候選一律不會被呼叫。
- **快速初稿失敗 ≠ 主要翻譯失敗**：前者只降級為直接翻譯；後者才依翻譯備援清單處理。
- 全部候選失敗：限流類顯示等待／可重試；設定錯誤須修正。播放視窗仍可選「先看，不要字幕」或
  「等字幕完成再播」，佇列不會被卡住。

## 6. 佇列與播放視窗的狀態文字

| 顯示 | 意義 |
| --- | --- |
| 辨識中／翻譯中 | 正在進行語音辨識或翻譯 |
| 快速初稿中 | Azure 初稿階段 |
| 精修中 | Groq 精修階段 |
| 等待額度恢復／等待額度中（N 秒後重試） | 遇到限流，依服務回報或冷卻時間等待；無可靠數值時只顯示「冷卻中」，不顯示假倒數 |
| 使用備援：模型（原因） | 已切到備援候選 |
| 已恢復主服務：模型 | 主服務探測成功 |
| Azure 初稿失敗，降級為直接翻譯 | 初稿降級，字幕照常產生 |
| 翻譯服務失敗（原因） | 主要翻譯所有候選皆失敗 |
| 字幕已到 mm:ss，其餘背景處理中 | 前段已可播放，其餘漸進處理 |

## 7. 憑證儲存位置

API 金鑰不會出現在模型目錄、設定快照、worker job、日誌，前端只取得遮罩與驗證狀態。

- Windows：使用者範圍 DPAPI 加密。
- 其他平台：OS keyring。
- 環境變數：連線可改讀環境變數（變數名稱 `OH_STREAMER_SUBTITLE_KEY_<模型ID正規化>`），僅供 CI 或本機測試，
  不寫入磁碟。連線卡片會標示來源為 DPAPI／Keychain／環境變數。

遠端 URL 須用 HTTPS（localhost 可用 HTTP），不跟隨帶憑證的重新導向。

## 8. 設定與排程（技術摘要）

- `subtitle_profile`：版本化設定（`schema_version` 1，`plan_version` `cloud-first-1`），含
  `active_mode` 與 `cloud`／`local`／`custom` 三份 profile（asr、translation、draft、processing、
  whisper_policy、fallback）。內容不含金鑰。
- 新工作建立時解析並凍結 `subtitle_resolved`（`subtitle_runtime_contract="cloud-first-1"`），
  含具體模型綁定與備援順序；之後修改全域設定不影響已排程工作。流程為 `direct`（無初稿）
  或 `draft_refine`。
- 備援執行在 `subtitles/fallback.py`：有限重試、Retry-After、跨程序 SQLite 冷卻帳本
  （AppData 內 `subtitle-fallback.sqlite3`，以端點＋憑證摘要識別帳戶，同金鑰不重複計算額度），
  事件 `type="subtitle_fallback"` 寫入工作的 `subtitle.fallback`。
- 舊設定轉為 profile 後原始資料保留；舊工作仍可讀取。
- 其他既有設定：`subtitle_primary`、`subtitle_comparison_enabled`、`subtitle_comparison_rows`
  （比較軌為額外字幕軌，不取代主字幕，翻譯表與快取隔離）、`subtitle_translation_igpu`
  （實驗性核顯翻譯，預設關閉；失敗回退 RTX，電池供電或播放器忙碌時暫停）。

## 9. 模型管理

ASR 與翻譯模型分開管理。內建模型保留登錄；使用者新增的模型可移除登錄（不刪除檔案）。
被設定或佇列引用的模型拒絕移除並顯示原因。

支援已知本機引擎、GGUF 翻譯配方與 OpenAI-compatible API：

- ASR：`/audio/transcriptions`，須回傳 `verbose_json` 實際片段時間碼；長音訊以五分鐘分段處理。
- 翻譯：`/chat/completions`，須保留逐行編號。

新增前須通過實際推論測試（辨識需語音樣本）；連線成功或檔案存在本身不算通過。
雲端測試與工作會上傳音訊或文字，費用依服務商計算。「通過測試」只是狀態提示，
不保證日後網路、配額或模型仍可用；實際失敗會回報在各字幕列。

  <https://console.groq.com/docs/deprecations>

  <https://azure.microsoft.com/en-us/pricing/details/cognitive-services/translator/>
